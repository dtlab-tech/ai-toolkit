### UC-01: Enumerate Phases Only

| Field | Value |
|---|---|
| Actor | `gaia-generate-work-breakdown` (repurposed) |
| Priority | Must |
| Preconditions | A feature's Work Breakdown skeleton has not yet been generated (or is being regenerated from scratch) |
| Trigger | `pm-phase2.js` dispatches the phase-enumeration call |

> **Legend:** **Actor** — who/what initiates or participates in this use case. **Priority** —
> MoSCoW (Must/Should/Could). **Preconditions** — what must already be true before this use case
> can start. **Trigger** — the event that starts it.

The SAME agent name (`gaia-generate-work-breakdown`) that previously decided the ENTIRE task graph
in one call is repurposed to decide ONLY the ordered list of phases — bounded by UC count
(typically 10-20 rows for a real feature), the same order of magnitude as Requirements'/Tech-Spec's
own index-level skeleton calls, neither of which has ever shown this failure mode. Mirrors
Requirements/Tech-Spec's own precedent exactly: a lightweight index decision first, heavier
per-item detail deferred to later, bounded calls (UC-02).

1. **Input is unchanged from the current (post-FTR-032) skeleton call.** Requirements (full text)
   and Tech-Spec (skeleton only) are inlined into the prompt exactly as FTR-032 already
   established — this UC does not touch that mechanism.
2. **Output shrinks to phase-only fields.** `id`, `type`, `sourceUC`, `commit` — the same fields
   `index.json`'s own phase objects already carry today — plus `title` (needed to render each
   phase's own detail file, same as today). `taskIds` is NOT produced here (UC-02 decides it,
   phase by phase) and `context` (the one genuinely narrative phase-detail field) is deferred to
   each phase's own task-generation call (UC-02), which has the fuller picture of that phase's
   actual tasks needed to write a meaningful 2-4 sentence context.
3. **No `needsComponentDetail` at this tier.** Deciding WHICH phases exist (one per UC, plus
   INFRA) needs only Requirements' own UC list and Tech-Spec's own feature-wide sections — not
   per-component detail; that need arises, if at all, during UC-02's own per-phase task
   decomposition, not here.
4. **INFRA phase ordering is unchanged.** If present, it is enumerated first — exactly as today's
   single-call generator already guarantees via its own "INFRA phase first" rule.

- **Phase ID:** US-03

- **Source UC:** UC-03
- **Title:** As the coordinator, I want pm-phase2.js to generate the AC-Task matrix right after rendering the Work Breakdown, so that it ships at Gate 2 alongside the existing deliverables with no new blocking condition
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-03 pm-phase2.js wiring

**Context:**

The smallest possible integration surface: one new activity block, inserted after an existing
one, with no change to any existing pass/fail branch. There is nothing to resume or retry here
(unlike the skeleton/per-item generation loops in FTR-020/021) — this step is a single
deterministic subprocess call with no LLM involved, so it either completes or the whole workflow
run fails, exactly like the existing `wb-render.js` step it sits next to.

**Tasks in this phase:**

- `US-03-TASK-BE-01` — wire the new activity block into `pm-phase2.js`
- `US-03-TASK-TEST-01` — integration test asserting the matrix file and its Gate 2 payload path

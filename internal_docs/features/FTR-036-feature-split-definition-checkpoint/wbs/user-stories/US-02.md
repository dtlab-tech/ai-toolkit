### US-02

- **Phase ID:** US-02
- **Type:** user-story
- **Source UC:** UC-02
- **Title:** As a user, I want to accept, edit or reject the split proposal in the main loop, so that children are created only after I confirm and a rejected feature continues as standalone
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-02 accept, edit or reject split proposal

**Context:**

US-01 built Phase 3a and the CHECKPOINT return, and the earlier INFRA phase built validate-proposal. This phase handles the user's decision after the proposal is shown. The agent gets write-mode branches for reject (standalone) and accept (parent write, register, then apply). It also gets an edit loop and partial-apply recovery. The skill collects and relays the decision. Agent tasks come first, then skill tasks, then the static text tests.

**Tasks in this phase:**

- `US-02-TASK-BE-01` — Add standalone write branch with no-overwrite guard and register to the agent
- `US-02-TASK-BE-02` — Add checkpoint reject re-invocation handling to the agent
- `US-02-TASK-BE-03` — Add accept split branch to the agent with parent register before apply
- `US-02-TASK-BE-04` — Add edit validation loop to the agent
- `US-02-TASK-BE-05` — Add partial apply failure reporting to the agent
- `US-02-TASK-BE-06` — Add decision collection and re-invocation to the skill
- `US-02-TASK-BE-07` — Add partial apply failure recovery offer to the skill
- `US-02-TASK-TEST-01` — Add static tests pinning agent decision handling text
- `US-02-TASK-TEST-02` — Add static tests pinning skill decision relay text

**Depends on phases:** US-01, INFRA

### US-02

- **Phase ID:** US-02
- **Type:** user-story
- **Source UC:** UC-02, UC-05
- **Title:** As the coordinator, I want to validate the skeleton structurally before spending per-task tokens, so that a broken graph is rejected before any per-task call is dispatched
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-02 skeleton structural pre-checks

**Context:**

This phase wires the already-extracted `wb-graph-checks.js` (built in INFRA) into
`wb-validate.js` itself, replacing 10 of its 23 inline checks (checks 3, 5–14, 19–21) with calls
into the shared module, and switches its input-loading from a direct `JSON.parse` to the new
`wbs-assembler.loadWorkBreakdown`. The two changes are kept as separate tasks (BE-01 then BE-02)
because they touch the same file in two independent ways — mixing them would make a failed
verification harder to attribute to one cause or the other. The regression test (TEST-01) is the
hard proof that this extraction changed nothing observable: `wb-validate.js`'s JSON report and
exit code must be byte-identical to the pre-extraction baseline for every existing fixture.

**Tasks in this phase:**

- `US-02-TASK-BE-01` — wire `wb-validate.js` to call `wb-graph-checks.js` for checks 3, 5–14, 19–21
- `US-02-TASK-BE-02` — wire `wb-validate.js` to load input via `wbs-assembler.loadWorkBreakdown`
- `US-02-TASK-TEST-01` — regression test proving byte-identical output before/after the extraction

**Depends on phases:** INFRA (needs `wb-graph-checks.js` and `wbs-assembler.js` to exist first)

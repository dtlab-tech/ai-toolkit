### US-05

- **Phase ID:** US-05
- **Type:** user-story
- **Source UC:** UC-05
- **Title:** As the coordinator, I want wb-render.js to assemble its input from either format, so that final Work Breakdown .md/.csv output is unaffected by this feature
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-05 renderer directory-format support

**Context:**

This phase makes `wb-render.js` consume the same `wbs-assembler.loadWorkBreakdown` loader as
`wb-validate.js` (US-02), so the final `{PREFIX}-Work-Breakdown.md`/`.csv` render identically
regardless of which input format (split directory or legacy single JSON) produced the in-memory
structure. `renderMarkdown`/`renderCsv`/`computePhaseDependsOn`/`sanitizeField`/
`fencedCommandBlock`/`taskAnchor` themselves are not touched — only the top-of-file
read-and-parse lines change. The regression test (TEST-01) is the hard proof: render from the
`wbs/` directory fixture and from the equivalent legacy `FTR-020-Work-Breakdown.json`,
and assert byte-identical `.md`/`.csv` bytes.

**Tasks in this phase:**

- `US-05-TASK-BE-01` — wire `wb-render.js` to load input via `wbs-assembler.loadWorkBreakdown`
- `US-05-TASK-TEST-01` — regression test proving byte-identical rendered output for both input formats

**Depends on phases:** INFRA (needs `wbs-assembler.js` to exist first)

### US-03

- **Phase ID:** US-03
- **Type:** user-story
- **Source UC:** UC-03
- **Title:** As a user, I want an accepted split applied or a rejected one to continue unchanged, so that nothing is created without my confirmation
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-03 apply accepted split or continue unchanged

**Context:**

US-02 built the Step 1a statuses, the proposal presentation, the edit loop, and a short statement of the accept, reject and unanswered outcomes. This phase fills in what happens after the user answers. It covers the apply call, the report of created children, the apply failure and retry paths, and rejection with discarded edits. These are all SKILL.md text in the main loop, followed by static tests that pin them. The tasks build on the US-02 Step 1a text.

**Tasks in this phase:**

- `US-03-TASK-BE-01` — Add apply invocation with the confirmed edited proposal to Step 1a accept
- `US-03-TASK-BE-02` — Add created-children report and parent stop after successful apply
- `US-03-TASK-BE-03` — Add apply failure handling to Step 1a accept
- `US-03-TASK-BE-04` — Add retry and unanswered-proposal rerun wording to Step 1a
- `US-03-TASK-BE-05` — Add edit-then-reject discard rule to Step 1a reject branch
- `US-03-TASK-TEST-01` — Add static tests for the Step 1a apply and success path
- `US-03-TASK-TEST-02` — Add static tests for Step 1a reject, failure, retry and unanswered text

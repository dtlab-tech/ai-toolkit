### US-02

- **Phase ID:** US-02
- **Type:** user-story
- **Source UC:** UC-02
- **Title:** As a user, I want a split proposal presented before Gate 1 that I can accept, edit or reject, so that I control how an oversized feature is divided
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-02 split proposal and Step 1a presentation

**Context:**

US-01 built the check-size measurement and a measured proposal envelope with empty keywords. This phase adds the deterministic child grouping and foundation mapping that fill the proposal (T-6, T-7). It also adds the Step 1a text in the implement-feature skill that presents the proposal and collects accept, edit or reject. The BE tasks come first, then the skill tasks, then the tests that pin them.

**Tasks in this phase:**

- `US-02-TASK-BE-01` — Compute child count and use-case blocks for the measured proposal
- `US-02-TASK-BE-02` — Assign components to child blocks and fill child fields
- `US-02-TASK-BE-03` — Map depth-0 components to the shared foundation child
- `US-02-TASK-BE-04` — Add Step 1a status branches to implement-feature skill
- `US-02-TASK-BE-05` — Add split-proposed Keywords derivation and proposal presentation to Step 1a
- `US-02-TASK-BE-06` — Add edit loop with minChildren refusal and re-presentation to Step 1a
- `US-02-TASK-BE-07` — Add accept and reject outcomes and no-write guarantees to Step 1a
- `US-02-TASK-TEST-01` — Test deterministic child grouping and component assignment in check-size
- `US-02-TASK-TEST-02` — Test shared foundation mapping and empty keywords in check-size proposal
- `US-02-TASK-TEST-03` — Extend static tests to pin the Step 1a skill text

**Depends on phases:** US-01

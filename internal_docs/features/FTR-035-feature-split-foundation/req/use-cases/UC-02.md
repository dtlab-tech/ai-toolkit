### UC-02: Decide whether a feature is new

| Field | Value |
|-------|-------|
| Actor | Calling feature script |
| Preconditions | The caller has a feature folder path (`featureDir`). The folder may or may not exist yet. The configuration is not needed for this use case. |
| Trigger | A caller invokes `isNewFeature(featureDir)`. |
| Priority | Must |

**Main flow:**
1. The caller passes `featureDir` to `isNewFeature`.
2. If `featureDir` does not exist, return `{ isNew: true, reason }`, where the reason states that the folder does not exist yet. Stop.
3. Check whether `featureDir` contains `{PREFIX}-Approvals.md`, where `{PREFIX}` is the feature's prefix (for example `FTR-035-Approvals.md`). If it does, return `{ isNew: false, reason }`, where the reason identifies this marker. Stop.
4. Check whether `featureDir` contains a `wbs/` directory. If it does, return `{ isNew: false, reason }`, where the reason identifies this marker. Stop.
5. Check whether `featureDir` contains `epic.md`. If it does, return `{ isNew: false, reason }`, where the reason identifies this marker. Stop.
6. Do not inspect generated `req/` or `spec/` folders. They do not affect the result.
7. Do not look for executor runs. Executor runs are stored in the git common directory, and the checks in steps 3 to 5 already cover them.
8. If none of the markers in steps 3 to 5 is present, return `{ isNew: true, reason }`, where the reason states that no non-new marker was found.

**Alternative flows:**
- `featureDir` does not exist yet → `isNew: true` (step 2).
- `featureDir` contains only generated `req/` and `spec/` → `isNew: true`, the same as a folder with no markers (steps 6 and 8).
- `featureDir` contains `req/` and `spec/` that were regenerated with `--force` → still `isNew: true`. Regeneration does not change the result.
- `featureDir` contains more than one marker → `isNew: false`. The reason names one of the markers present (step 3 to 5). The feature does not say which one.

**Error flows:**
- `featureDir` exists but cannot be read, so the markers cannot be checked → not specified in `feature.md`. See the open question in Postconditions.

**Postconditions:**
- The caller receives `{ isNew, reason }`.
- The feature folder is unchanged. This use case only reads.
- Open question: `feature.md` does not specify what `isNewFeature` returns when `featureDir` exists but cannot be read, so that the markers in steps 3 to 5 cannot be checked. It is not stated whether this is an error (and under what code) or a `isNew` value. Under D-07 the function returns a determination only from markers it checked, so an unreadable folder cannot be confirmed as new by that rule. This is a judgement not stated in `feature.md`; it needs a decision at Gate 1 and an acceptance criterion.
- Open question: `feature.md` does not specify the order in which steps 3 to 5 are checked or the exact wording of `reason`. The order can change which marker is named in the reason, but it does not change `isNew`.

### UC-05: Register a standalone feature

| Field | Value |
|-------|-------|
| Actor | Calling feature script |
| Preconditions | The feature is not split. Its folder exists and holds the `feature.md` just written for it (D-20). The features root can be resolved with `ai-toolkit resolve-features-root` (D-22). The caller supplies the Keywords for the feature. |
| Trigger | The feature's `feature.md` is written by a standalone definition, or the caller runs `register` with a feature directory and Keywords (D-25). |
| Priority | Must |

**Main flow:**
1. The caller runs `feature-split.js register` through the facade with `--features-root`, the feature directory and the Keywords (D-23, D-25).
2. The module resolves the features root and the registry path with `ai-toolkit resolve-features-root`. No path is hard-coded (D-22).
3. The module reads the feature's `feature.md` and takes the feature ID and title from it.
4. The module takes the entry Summary as the first sentence of the feature's Summary section (D-20).
5. The module looks for an existing registry entry with that ID. If none exists, it adds one entry in the existing registry format (D-18): heading, `Keywords` (from the caller), `Status: defined`, `Summary`, and `Detail` as a link to the feature's `feature.md`. The entry has no `Parent:` and no `Depends on:` line.
6. If `REGISTRY.md` does not exist, the module creates it with the new entry (D-21).
7. The module writes the registry through a temp file and a rename, so the file is replaced in one step (D-21).
8. The module prints `{ id, status: "defined" }` on stdout and exits 0 (D-25, D-23).

**Alternative flows:**
- `REGISTRY.md` is missing → the module creates it containing only this entry, and the flow continues from step 7 (D-21).
- An entry for this ID already exists, with status `defined`, `completed` or `epic` → no second entry is added, and the existing entry is not changed. Re-running `register` does not duplicate the entry (D-21).
- The feature later becomes a split epic → the change is made by UC-04 to this same entry in place, with status `epic`, not by a new entry (D-19).

**Error flows:**
- The features root cannot be resolved → the module reports the error on stdout and exits 1. Nothing is written (D-22, D-23).
- The registry cannot be read or written → nothing is registered. The module reports the error and exits 1. The registry is not left partly written, because the write is a temp-and-rename (D-21). The run's own moved-into-place files are removed. For a `register` call on its own that set is empty, because only the registry is written.
- An existing entry for this ID has any other status (not `defined`, `completed` or `epic`) → the entry is left untouched and is not treated as an epic. No duplicate is added (D-18, D-21).
- `feature.md` is missing or unreadable → open question: `feature.md` does not say which error applies or whether an entry is written. No entry is written until this is decided (see Postconditions).
- Keywords are missing or empty → open question: `feature.md` does not say whether `register` rejects the call or writes an empty `Keywords` line (see Postconditions).

**Postconditions:**
- `REGISTRY.md` contains exactly one entry for the feature ID, in the existing format, with `Status: defined`, the caller's Keywords, the first sentence of the Summary and a `Detail` link to the feature's `feature.md`. The entry has no `Parent:` or `Depends on:` line, so readers treat it as standalone.
- The registry was written by temp-and-rename, and no temp file is left behind (D-21).
- The stdout result is `{ id, status: "defined" }` and the exit code is 0 (D-25).
- Open question: `feature.md` does not say whether the ID is read from the folder name or from its "Feature ID" section. The two should agree, and the source must be fixed before implementation.
- Open question: when an entry for the ID already exists, `feature.md` does not say what `register` returns. Returning `status: "defined"` would misreport an entry whose status is `completed` or `epic`.
- Open question: `feature.md` does not define the error for a missing or unreadable `feature.md`, or the behaviour for missing or empty Keywords.

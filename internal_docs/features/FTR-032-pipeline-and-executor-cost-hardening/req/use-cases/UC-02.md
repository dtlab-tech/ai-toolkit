### UC-02: Persist Turn-by-Turn Dispatch Evidence for Implementation/Review

| Field | Value |
|---|---|
| Actor | `dispatchTaskAttempt` / `runReview` (`lib/task-executor/index.js`) |
| Priority | Must |
| Preconditions | A task attempt is being dispatched (implementation) or has passed verification and is proceeding to review |
| Trigger | `dispatchTaskAttempt` or `runReview` spawns its headless `claude.exe` subprocess |

> **Legend:** **Actor** — who/what initiates or participates in this use case. **Priority** —
> MoSCoW (Must/Should/Could). **Preconditions** — what must already be true before this use case
> can start. **Trigger** — the event that starts it.

Reported against a real run (`Fincantieri.ISDM.JobScheduler` FTR-012, toolkit v0.22.0): a task
whose entire job was a 4-line SQL rename already present in the codebase still cost ~15 minutes of
implementation dispatch and ~5 minutes of review dispatch to conclude "nothing to do." The
reporting peer could not root-cause WHERE that time went because the task executor, unlike
`pm-phase1`/`pm-phase2`, persists no turn-by-turn record of what a dispatched agent actually did —
only the final outcome (pass/fail, checkpointed/blocked). This UC does not itself diagnose or fix
the cost; it makes future cost investigations tractable by capturing the raw material, mirroring
the existing `lib/workflow-worker-evidence.js` convention `pm-phase1`/`pm-phase2` already use for
their own worker calls.

1. **Persist one evidence file per dispatch attempt.** Each real implementation dispatch
   (`dispatchTaskAttempt`) and each real review dispatch (`runReview`) writes its own raw
   transcript/response to a new evidence file, under the run's own execution-root directory,
   keyed by taskId/attemptNumber/dispatch-kind (implementation vs. review) — exact path/filename
   convention resolved in Tech-Spec.
2. **Capture happens regardless of outcome.** A dispatch that times out, errors, or returns a
   result verification/review later rejects still has its raw transcript persisted — this UC
   captures what happened, not whether it was a success.
3. **No interpretation, no new behavior change.** This UC adds a write-only side effect to an
   existing dispatch; it does not change what gets dispatched, how retries work, or any
   pass/fail/terminal-status decision anywhere in `_runTaskToResolution`.
4. **Independently readable.** The evidence file for a given attempt must be readable on its own,
   without needing the run to have reached a terminal state — the same "evidence survives
   independent of in-progress run state" property `lib/workflow-worker-evidence.js` already has.

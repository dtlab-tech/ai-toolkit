### US-05

- **Phase ID:** US-05
- **Type:** user-story
- **Source UC:** UC-05
- **Title:** As the coordinator, I want a loader/renderer that reassembles spec/index.md and spec/components/*.md back into the unchanged 12-section Tech-Spec document, so that every downstream consumer keeps reading {PREFIX}-Tech-Spec.md exactly as before
- **Commit type:** feat
- **Commit scope:** —
- **Commit subject:** implement US-05 tech-spec assembler

**Context:**

The feature's structurally hardest piece, by design isolated into its own phase with no
dependency on US-01/US-03 so it can be built and unit-tested against hand-built fixtures
independently of the agents that will eventually produce real skeleton/component content. Unlike
`req-assembler.js`'s single-section splice (FTR-021), this assembler must route content into
*three* different numbered sections (3, 4, 5) by each component's own `Domain`, plus rebuild a
fourth (10, Testing Strategy) unconditionally from every component — the one piece of this
feature's design that genuinely has no precedent to copy verbatim from FTR-020/021, only
principles to reuse (splice via `findSectionRange`, parse tables via `parseTableRows`, both
already exported from `req-assembler.js`).

**Tasks in this phase:**

- `US-05-TASK-BE-01` — `loadTechSpec` (directory/legacy loader + domain-routed section rebuild)
- `US-05-TASK-TEST-01` — unit tests (BE/FE/unclassified routing, legacy path, structured errors)

**Depends on phases:** none

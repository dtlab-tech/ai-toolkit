**Context:**

This is where every other phase's output gets wired together into `pm-phase1.js`'s actual
`generateRequirements()` function: the skeleton call (BE-01), the structural pre-check gate using
`req-skeleton-check.js` (BE-02), the per-UC generation loop with resume-by-existence (BE-03), and
the final assembly hookup via `req-assembler.js` writing to `file('Requirements')` (BE-04). Task
order within this phase is literal — each task's `dependsOn` reflects the exact sequential
position these steps occupy inside `generateRequirements()`'s body (see Tech-Spec §5 for the full
pseudocode all four BE tasks below implement piece by piece). `generateRequirements()` replaces
the current `requirements = () => c.worker(reqId, featurePath, { outputs: [output('Requirements')] })`
and is called from the same two existing call sites (initial generation and the
`needsRequirementsFix` revision branch) — nothing about *when* Requirements gets (re)generated
changes, only *how* the generation itself happens.
